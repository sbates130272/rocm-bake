  --extra-index-url https://pypi.org/simple \
  "rocm-torch[device-gfx1151]"

Reading the versions

A version says which ROCm a wheel was built against. Nothing in a filename says which GPU: torch for two architectures is the same filename and differs by tens of MB of device code. That is what the per-arch index path and the rocm-torch metapackage carry, and why installing through the index is the only correct way to get these.

The extra index is not optional — ordinary dependencies resolve from PyPI. Our wheels win over same-named PyPI projects because the metapackage pins exact versions whose local segment (+rocm…) upstream cannot match.

Platform tags differ by wheel and are not a choice: auditwheel grants a manylinux tag only where the compiled code's glibc symbols allow one. Some wheels here reference symbols newer than any defined policy and stay linux_x86_64; some contain no CPU code at all. Each architecture's index lists the measured tag and the glibc behind it, under Platform tags.
